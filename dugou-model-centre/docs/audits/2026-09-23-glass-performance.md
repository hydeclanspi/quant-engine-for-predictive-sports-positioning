# 液态玻璃性能与画质设置

## 2026-09-25：材质与背景独立控制

Console → 界面布局 → 画质模式拆成两组，适用于全部 8 个主题：

| 设置 | 选项 | 默认 | 控制范围 |
| --- | --- | --- | --- |
| 液态玻璃 | 流畅 / 满帧 | 满帧 | 卡片实时背景模糊、鼠标追光、材质交互；满帧是完整材质档位，不是固定 FPS 保证 |
| 渲染背景 | 流畅 / 满画质 | 流畅 | 静态底图与局部光效 / 原动态背景；Console 拖尾与装饰循环跟随背景档位 |

- 保留旧字段 `liquidGlassQuality`，其语义收窄为背景档位，已保存的背景选择不变。新增 `liquidGlassMaterialQuality`；旧配置缺少它时默认 `full`，因此原「流畅」用户也得到满帧玻璃 + 流畅背景。
- CSS `liquid-glass-smooth` 只限制材质；`liquid-background-smooth` 限制背景和装饰。切换任一项不改另一项，也不会触发模型重算。
- 只有背景「满画质」沿用确认提醒；取消不修改设置。玻璃「满帧」直接生效。
- 两项均为当前设备偏好；预览隔离、历史快照、导入 merge/replace、Git 同步均保留对应选择，不改业务数据。
- 浏览器验证四种组合、背景确认/取消、三个深色旗舰主题及 390px 窄屏。默认组合下 Console Canvas 为 0；红果卡片为 `blur(30px) saturate(2)`，三个深色旗舰为 `blur(18px) saturate(1.4)`；切换玻璃流畅后为 `none`。
- 最终检查：37 个测试文件、358 项通过；构建通过；ESLint 0 errors / 77 warnings（既有）；`git diff --check` 通过。

以下记录为 9 月 23–24 日首次优化时的行为与验收，统一画质开关现已由上述两组独立设置取代。

## 初次优化实现的行为

- Console → 界面布局新增全局画质选择，现有 8 个主题共用。旧配置或无效配置默认「流畅」。
- 点击「满画质」先显示警告；取消、Escape 或关闭不保存，明确确认后才挂载原渲染器。原旗舰 shader 和满画质渲染分支保留。
- 画质保留本机选择。云/Git 拉取、JSON 导入的 merge/replace、历史快照都不能替本机切换画质。主题仍按既有规则同步。
- 流畅的光谱、璇玑、牵星、流光溢彩、红果使用预生成 WebP；晴光、月汐、暖砂沿用静态 CSS 构图。
- 光谱双光带独立为一张透明贴图；璇玑、牵星各有一个低对比局部光晕。仅滚动时更新局部层的 transform / opacity，停止滚动后无后台循环。支持减少动态效果、隐藏页暂停和解绑清理。
- 流畅卡片保留半透明填色、边缘高光、描边和阴影，用预先柔化的背景形成透色；移除卡片和嵌套控件的实时 backdrop-filter。仅滚动后的顶栏和打开的导航下拉保留 6px 模糊。
- 流畅关闭全卡片鼠标扫描与 Console 光标粒子画布；冻结战报装饰循环，移除大批 Console 控件常驻 will-change。交互反馈、业务数据和加载指示器保留。

## 成本来自哪里

这是代码路径审计和局部运行验证，不能代替目标低配设备上的完整性能录制。

| 路径 | 原有成本 | 本次处理 |
| --- | --- | --- |
| GPU / 光栅与合成 | 全屏 WebGL + flowmap 双缓冲 + 每像素噪声；旗舰闲时 12fps、交互 30fps | 流畅不创建 WebGL 上下文，不执行 shader 或 flowmap，背景静态 |
| 玻璃采样 | 深色卡片 18px 模糊、其它层额外模糊；动态背景不断改变背板采样内容 | 卡片不再实时采样，导航模糊限制到 6px；透色和玻璃高光保留 |
| JS 主线程 / 布局 | 每次 mousemove 遍历全部 glow-card，布局读取与样式写入交错 | 流畅不订阅；满画质同一帧合并事件，先读取、再写入，仅更新可见卡片 |
| JS 主线程 / 模型 | 主题保存广播通用 data-changed，清分析/战报缓存，Console 排入四组同步计算 | 仅外观补丁携带 uiOnly；业务计算订阅者跳过，真正数据与参数保存照常失效 |
| Console 分析与自适应权重 | 首次挂载在主线程同步计算；完整校准和权重卡还重复计算建议 | 四组分析移到 Worker；复用完整校准中的权重结果，外观修改不重启任务 |

原旗舰在 1440×900、DPR≥1.2 下主画布约 105 万像素，flowmap 约 6.6 万像素。按 30fps 估算，两次绘制每秒约 3346 万片段调用，尚未计入噪声函数、卡片模糊和其他页面合成。这是源码尺寸与帧率的推算，不是 GPU 时间或帧率实测。

静态图只消除背景持续绘制；如果仍保留大量嵌套 backdrop-filter，滚动内容时仍可能昂贵。因此本次同时削减采样层和主线程的无关重算。

## Console 后台计算

独立 demo 数据诊断使用 96 笔投资（225 个有效样本）：评分约 12 ms，各 Kelly 阶段约 0.7–0.8 s，模型验证约 13.1 s；完整校准与独立自适应权重在各自 30 s 诊断上限仍未结束。这是本地单次诊断，用于定位同步长任务，不是跨机器基准，也不能据此推断死循环。

- 主线程捕获当前配置、投资、球队资料的快照，保留 preview / Time Machine 的读取语义，再传入专属 Worker。
- 计算公式和时间验证保持原样；只返回可结构化克隆的展示数据，预测函数留在引擎内。完整校准已经算出的权重建议复用一次。
- 分评分、Kelly、校准、验证四阶段返回；页面先可交互，加载期间不展示伪结果，也不允许应用尚未返回的建议。
- 真正数据变化或离开页面终止旧 Worker；每次新任务使用新快照和新缓存。成功、异常或 120 s 超时清理 Worker；失败显示不可用与重试，不退回主线程同步计算。
- New / Portfolio 的完整预测校准不再附带只供 Console 使用的权重调优诊断；缓存按选项隔离，预测拟合、组合参数和预测概率保持一致。浏览器复测 New 不再出现原先这段调优造成的验收超时。
- Worker 隔离的是 Console 交互阻塞，不会凭空降低算法 CPU 总量；其它页面保留实际使用的模型计算，未整体迁移。

## AI 框文字

光谱、璇玑、牵星的 New Quick Input 和 Settle AI 面板改用主题的实色主文字、次级文字与按钮前景，移除标题浮雕阴影；深色表单、结果区与单场 AI 控件统一对比关系。满画质和流畅共同生效。

## 资源与维护

`python3 scripts/generate-glass-backdrops.py` 生成固定种子的背景，依赖 NumPy 和 Pillow，不依赖网络或浏览器。生成结果是原配色/构图的静态近似，不声称是完整 shader 截图。

- 横版：1600×1000；竖版：800×1200，由 picture 按视口比例选择。
- 双光带：1024×384 RGBA，仅光谱加载。
- 全部 11 张 WebP 合计 **141,594 字节（138.3 KiB）**；页面只请求当前主题对应资源，不预加载全部主题。
- 光谱宽屏实际背景资源约 31 KiB。压缩体积不等于解码内存；1600×1000 RGBA 纹理约 6.1 MiB。
